# Incident Documentation

## Purpose

Accurate documentation ensures security incidents can be reviewed, reproduced, and resolved efficiently.

## Recommended Incident Report Format

### Incident Summary

Provide a brief overview of the event.

### Timeline

Document significant events in chronological order.

### Affected Assets

Identify:

* Systems
* User accounts
* IP addresses
* Applications

### Evidence

Include references to:

* Security logs
* Alerts
* Event IDs
* Screenshots (when available)

### Analysis

Explain the findings based on available evidence.

### Containment

Document actions taken to reduce risk.

### Recovery

Describe how affected systems were restored.

### Lessons Learned

Identify improvements that could reduce the likelihood or impact of similar incidents in the future.
