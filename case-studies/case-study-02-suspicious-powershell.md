# Case Study 02 – Suspicious PowerShell Execution (Fictional Scenario)

## Scenario

This fictional scenario demonstrates how a SOC analyst might investigate suspicious PowerShell activity detected on an endpoint.

## Alert Summary

**Alert Type:** Suspicious PowerShell Execution

**Severity:** High

**Source:** Endpoint Security Monitoring

## Initial Observation

A security alert was generated after PowerShell executed a command containing encoded content and attempted to communicate with an external destination.

## Investigation Process

A SOC analyst would review:

* The user account that executed the command
* The affected endpoint
* The parent process that launched PowerShell
* The command-line arguments
* Network connections generated by the process
* Related security events before and after execution

## Potential Risks

Suspicious PowerShell activity may indicate:

* Malware execution
* Unauthorized administrative activity
* Downloading additional payloads
* Attempts to bypass security controls
* Credential theft activity

## Investigation Questions

* Was the PowerShell activity expected?
* Does the user normally perform administrative tasks?
* Was the command executed from a trusted application?
* Did the system make suspicious network connections?
* Were additional files created or modified?

## Recommended Actions

* Collect relevant logs and evidence.
* Determine whether the activity was authorized.
* Isolate the endpoint if malicious activity is suspected.
* Search for similar activity across the environment.
* Escalate findings based on severity.

## Lessons Learned

PowerShell is a legitimate administrative tool but can also be abused by attackers. Analysts must evaluate context, user behavior, and supporting evidence before determining whether activity is malicious.
